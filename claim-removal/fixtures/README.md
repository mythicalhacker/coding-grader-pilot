# Fixed historical patch and test evidence

Eight SWE-bench Verified issues supplied 16 archived candidate patches, one benchmark-resolved and one benchmark-unresolved per issue. The four repositories are Astropy, Matplotlib, pytest and scikit-learn. Within each, we took the two lowest numeric eligible issue IDs after removing all issues from the earlier graded selection and discovery experiments and the xarray, Django and Matplotlib individual studies. Eligibility required both public submissions to have an applied patch, an actual terminal note, and opposite resolved flags that matched the pinned submission indexes. The issue IDs were frozen before any experimental grader saw a packet. [Selection record](selection.json)

For each patch, its problem statement, exact patch bytes and original terminal note are separate files. The source runs were the October 22, 2024 Claude 3.5 Haiku and updated Claude 3.5 Sonnet submissions. The original terminal note was recovered from the last assistant text before the trajectory’s submission marker. The provenance record pins the archived byte range and its hash as well as the note, patch, benchmark grading report and raw execution log. The benchmark was SWE-bench Verified at dataset revision c104f840cc67f8b6eec6f759ebc8b2693d585d4a. [File and line-level provenance](provenance.json) · [Dataset revision](https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified/tree/c104f840cc67f8b6eec6f759ebc8b2693d585d4a) · [Submission indexes](https://github.com/SWE-bench/experiments/tree/40f164d5b8f1d249bf95a6df8b74b577fd8e519d/evaluation/verified)

Each issue supplied the same five existing non-parameterized regression test IDs to both candidates. We sorted the dataset's PASS_TO_PASS list by ID, omitted parameterized IDs, and took the first five. This rule avoids ambiguous historical parser output for parameterized IDs truncated at spaces. Each patch's five recorded statuses were recovered from the historical execution of that exact patch. All 80 statuses matched both the corresponding lines of archived stdout (after removing ANSI color codes) and the machine-readable grading report. Those five statuses stayed fixed across note conditions. Fourteen patches passed all five. Two each failed one displayed test. This experiment reused historical executions.

Every candidate diff includes an author-written reproduction or test script. Graders can see those scripts in the fixed patch evidence. None modifies the upstream test files containing the five displayed checks. The five displayed results are from pre-existing benchmark regression tests. We did not present the issue-specific hidden test outcomes, full test counts or the resolved flags to graders. Removing claims from a closing note does not remove comments or assertions within a submitted patch.

The held-out benchmark verdict checks the full collection of issue-specific tests and existing regressions. Of eight unresolved patches, four failed only existing regressions, two failed only issue-specific tests and two failed both. A benchmark-resolved patch can have defects outside this suite. The four manually chosen repositories and the deliberately discordant patch pairs do not estimate the natural frequency of broken patches. [Held-out labels and failure IDs](heldout.json)
